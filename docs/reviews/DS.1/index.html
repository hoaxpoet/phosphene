DS.1 — the app adopts UzumeTokens

Presentation only. Nothing the user can do changed: no state machine, publisher, view model, accessibility identifier, copy string, keyboard shortcut or test expectation was touched. Every pair below is the same screen at the same window size, before and after the token swap.

before is main at caa69638. after is the DS.1 branch. Uzume is always dark (D-231 option A), so there is one appearance to review. This Mac is set to Light appearance, which is why the window chrome changes.

Four of twenty states are captured. The rest need a click or a keystroke, and driving the app's UI needs Accessibility permission for the terminal Claude Code runs in — it is not granted, so there is no way to press a button. Grant it (System Settings → Privacy & Security → Accessibility) and the remaining sixteen states can be captured the same way, unattended. Each uncaptured state below says why.

Idle

Three changes. The canvas moves from pure black to --color-canvas #0b0c10 — a warmer near-black, most visible against the window chrome. The wordmark takes --color-text-primary (ivory #f4f6f1, not pure white) and the secondary action takes --color-text-tertiary. And the window is now pinned dark: on this Mac, which is set to Light appearance, the title bar was light grey and the primary button was system blue. It is now dark with the Uzume violet, via .preferredColorScheme(.dark) and the package's own uzumeTint(). One thing to judge: the tint reaches the secondary Start listening now button too, so it reads violet rather than grey. That is native macOS behaviour for a tinted bordered button. If you want secondary actions to stay quiet, say so and I will scope the tint to the primary action only.

Preparation (in progress)

Canvas; the aggregate progress bar's track moves to --color-surface-selected and its fill to --color-text-secondary; the row divider to --color-line-subtle. The Cancel button is native and untouched apart from the appearance pin. Track status icons take the success / warning / danger roles — note the danger role is a warm salmon #ff8a75, not systemRed.

Playback — chrome visible

PerformanceBackdrop, renamed from OverlayBackdropStyle. The measured values do not move: .ultraThinMaterial + 45% black at radius 10. The artwork placeholder fill and the text ramp are the only changes to the card. The transport bar's radius becomes --radius-lg; its surface and coral glow still come from DashboardTokens — migrating those is a visible restyle, so it is left for DS.6 rather than smuggled into a mechanical sweep. Note: the preset behind the chrome differs between the two shots (Membrane vs Stave). They are different file identities to the planner, so it picked differently. The chrome is what to compare.

Playback — chrome hidden

The preset frame with the chrome auto-hidden. No token touches the renderer; this pair is here to prove it. Different presets, same reason as above.
